# 奇美官網內部資料端點：自動來源可行性核對

核對日期：2026-10-11（臺灣時間）。結論：**一般訪客流程可由 Node.js 自動讀取，仍是候選來源，尚不能稱穩定自動來源，也未接入資料庫或排程。** 此端點是官網內部使用、未公開文件化的 JSON 呼叫，不稱為公開 API。

## 實測與證據

| 檢查 | 結果 | 判讀 |
| --- | --- | --- |
| 無 Cookie／CSRF 直接 POST | 419 | 不能把它當無狀態公開 API 使用。 |
| 公開頁匿名 session + CSRF，再 POST `{ "date": "", "tags": "" }` | PowerShell 與 Node.js 各成功；200 JSON | 正常訪客流程目前可程式化。只保留狀態、筆數與欄位名稱，不儲存 session、token 或回應全文。 |
| 預設資料 | `specialEvent=1`、`permanentEvent=4`、`expoEvent=10` | 三組結構不同，不能直接當共用展覽模型。 |
| `date=2026-10-11` | `1／4／0` | 篩選結果為預設集合的子集；不應將其與全量同步筆數相比。 |
| `tags=68` | `1／0／0` | 篩選結果為預設集合的子集。標籤值來自當日公開頁的 `tagsJson`。 |
| 官網前端 `exev.js` | 首次載入與篩選皆 POST `date`、`tags`；未見分頁參數 | 沒有發現前端分頁，但不能排除伺服器隱含上限；仍須在資料量增長時核對畫面與回應。 |
| 來源身份與連結 | 限期特展 ID 1 個、活動 ID 10 個無重複；常設展 4 個詳情 URL 無重複；全部連結指向奇美網域 | `special:<id>`、`expo:<id>`、常設展 URL 可作候選來源鍵。特展 API 連結目前會導向更長的詳情 URL，不能直接用目前的 URL 鍵規則做 ID 去重。 |
| 當期特展 | 唯一特展的日期是 `2026.01.29 - 2027.01.10`，與[館方詳情頁](https://www.chimeimuseum.org/special-exhibition/68a68f0a422a6/68a68fa1d1a3b)一致 | 目前這一筆可安全解析日期；不能推論未來新展的格式。 |
| 活動日期 | 有多場次、`即日起`、`已開課`、只有時段等格式 | 活動不能自動塞進目前要求單一起訖日的公開展覽表。 |

本機可重跑 `npm run probe:chimei`。指令先檢查 robots，再取公開頁匿名 cookie 與 CSRF meta，最後只送一次預設查詢；有逾時、回應大小、內容型別、同網域、必要欄位與重複身份檢查。它只輸出檢查時間、各組筆數、欄位集合及可解析特展日期筆數；不寫資料庫，不下載圖片，也不儲存原始回應。執行前應保持低頻，若館方限制或拒絕，應停止而非繞過。

## 是否能啟用

目前可作**低頻候選來源監測**，不加入正式每日匯入。正式啟用前仍須：

1. 在不同日期重跑，確認匿名流程、三組 schema、正常資料量及新展上架行為；單日多次成功不算跨日穩定。
2. 以官網實際顯示項目核對完整度；若未來出現更多資料，檢查是否有隱含上限或未曝光的分頁。
3. 建立奇美專屬 adapter、日期待審分流、`sourceType + id` 來源鍵，並測試清單縮水／419／空回應不可覆蓋舊資料或刷新完整同步時間。
4. 公開持續同步前確認館方對第三方使用資料的條件；只保存必要事實欄位並導回官方詳情頁。

這些條件完成前，網站仍沿用既有的人工核對與來源監測，不能宣稱奇美已自動同步。
