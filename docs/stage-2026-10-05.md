## 下階段接手

1. **審查與修正流程。** 目前只有待審唯讀清單；若要人工補日期，先建立需輸入館方證據 URL、審查人與時間的修正紀錄，並使後續同步不覆蓋審核決定。不能僅因缺迄日就判斷為常設展。
2. **科工館來源。** 官方開放資料中，2026-10-05 尚未結束的 8 筆特展，多數 `Website` 空白，另一筆指向第三方網站；目前沒有逐筆可靠的館方詳情網址，因此尚未匯入。先核對館方展覽頁與可穩定對應的 ID，不能用館方首頁冒充展覽詳情頁。
3. **奇美與文化部資料。** 文化部 JSON 是跨館彙整來源；要查明分頁與完整度，處理同一奇美特展拆段展期，並與館方頁交叉核對，再作為補充來源。奇美仍是人工核對，未有自動匯入。
4. **科博館私人 API。** Key 核發後在伺服端使用，先核對回應格式、授權及速率限制，再改既有公開 JSON adapter；Key 不寫入前端或 Git。
5. **非同步與正式運作。** 現在每館可獨立執行匯入，GitHub Actions 亦各自定義工作，但沒有 Queue、退避重試、失敗佇列或通知。先做來源重試與部分失敗測試，再依量測選 PostgreSQL 工作表或 Redis/BullMQ。正式發布前仍需獨立 repo、資料庫與 Secret、手動同步驗證和線上監測。AWS 尚未實作。

作品集對外表述：目前可說「本機多來源標準化、隔離、去重與異動偵測已實作並測試」；不可說「四來源每日自動上線同步」或「已完成事件佇列／AWS」。
