# Event Radar｜面試用專案介紹

核對日：2026-10-18。這份講稿依目前程式碼、[進度紀錄](../STATUS.md)與已留下的驗證證據撰寫；完整原理、逐題追問和練習見[面試技術學習手冊](interview-study-guide.md)。數據是指定日期的快照，不是長期可用率或使用者成長。

## 一句話定位

Event Radar 是整合博物館與展演公開資料的資訊平台：它把不同來源的資料驗證、標準化、去重並記錄變更，將無法確認的紀錄留待人工核對，再提供可追溯的搜尋結果。

## 30 秒自我介紹

> 我獨立開發並部署 Event Radar，讓使用者搜尋博物館限期展，也能查看表演場次與海生館節目。後端用 Node.js、TypeScript、PostgreSQL，前端用 React。比較有挑戰的是各館 JSON／HTML 格式不同：我做來源 Adapter、嚴格日期與官方網址驗證、冪等匯入和欄位異動歷史。來源突然縮水或資料缺漏時，系統會待審或暫緩缺席判定，避免把不可靠的資訊直接展示。網站已在 Render 與 Neon 公開預覽，六個來源工作及歌劇院路徑曾手動在線上驗證；真正的每週排程與跨週穩定仍在觀察。

## 兩分鐘版本：問題、設計、結果

> 我想解決的問題是：博物館活動散在不同官網，格式不一致，而且日期或清單可能缺漏。只把網頁抓下來會造成重複、過期或錯誤展覽，所以我把資料品質放在抓取之後的整條流程。
>
> 每個來源先經自己的 Adapter，轉成限期展、表演或當日節目的領域資料。限期展必須有完整起訖日與可核對的官方網址；不完整資料留在 `source_records` 待審。匯入時用穩定來源鍵和 PostgreSQL 唯一約束防重複，對已存在的展覽比較欄位並寫入異動歷史。若官方清單突然變少或來源鍵大幅變動，系統不把舊展直接判定取消，而是保存待核對狀態。
>
> 資料庫另外區分展覽日期範圍、表演的多個場次、海生館某一天觀察到的節目時段，避免把「今天的餵食時間」誤當成每天都適用。公開 API 提供搜尋和來源狀態，React 顯示資料限制並連回館方。CI 跑型別、單元、隔離 PostgreSQL／HTTP 整合與 OpenAPI 回應契約測試。正式資料庫也做過一次備份及本機隔離還原驗證。
>
> 網站目前是公開技術預覽，不是已證明穩定營運的產品。接下來會觀察實際週排程、補強異地備份與來源故障處理，再用真實使用數據決定功能優先順序。

## 展示順序（約五分鐘）

1. 打開[公開預覽站](https://event-radar-preview.onrender.com/)：示範城市、館所、展期與明確免費篩選；點進展覽看官方來源。免費 Render 服務可能休眠，首次開啟較慢。
2. 說明一筆錯誤來源如何處理：缺日期或非官方網址不進公開搜尋；來源突然縮水不直接把舊展刪掉。
3. 說明重跑同一來源：同一來源鍵不新增第二筆；標題或日期變更才寫入 `exhibition_changes`。
4. 對比三種時間：`exhibitions` 的日期範圍、`event_sessions` 的逐場時間、海生館的 `observed_on` 加本地時段。
5. 展示[架構](architecture.md)、[ERD](erd.md)、[OpenAPI](openapi.yaml)及[測試與備份紀錄](stage-2026-10-18-neon-backup-drill.md)，主動交代還沒完成的能力。

## 可用於履歷的說法

> 獨立開發並部署 Event Radar 公開技術預覽，使用 React、Node.js／TypeScript 與 PostgreSQL 整合多來源展覽資料；實作來源 Adapter、嚴格日期驗證、冪等匯入、欄位異動紀錄、待審隔離與來源清單異常保護，並以隔離資料庫整合測試和 OpenAPI 契約驗證公開 API。

面試時可補充：2026-10-17 的線上手動 Actions 有六個來源工作成功；2026-10-18 的正式 Neon 資料做過一次本機備份與隔離還原。不要把**手動執行成功**說成**跨週排程穩定**，也不要把 GA4 自己的測試流量說成真實使用者成果。

## 一定要主動說清楚的邊界

| 主題 | 現況與準確說法 |
| --- | --- |
| 公開服務 | Render + Neon 公開預覽已上線；免費服務休眠與長期可用性仍待觀察。 |
| 週更新 | 六個來源工作及歌劇院曾手動在線上驗證；2026-10-20 的首次真實週二排程及跨週結果尚未發生。故宮北院雲端來源獨立停用，由本機人工同步。 |
| Queue | PostgreSQL `FETCH_SOURCE` 工作有去重、租約、有限重試、`dead` 與人工 replay；解析、異動及通知沒有拆成多階段 Queue。歌劇院目前是獨立同步路徑。 |
| 奇美 | 官網內部 JSON 端點是未公開文件化的來源；目前有本機候選 Adapter、人工快照與核對，並非穩定自動活動來源。 |
| 海生館每日節目 | 保存成功觀察日的節目與快照，不能據此保證未來每日時間或特殊日開館。 |
| 搜尋與流量 | 搜尋關鍵字目前用 `ILIKE`；Search Console 已處理 sitemap，仍無可宣稱的自然搜尋曝光或外部使用者數。 |
| 備份 | 正式 Neon 曾備份並在本機隔離庫還原；目前是單份未加密本機副本，沒有自動異地備份。 |
| 未實作 | 訂閱通知、Email／LINE、AWS、多階段 production Queue、完整奇美與沖繩自動來源。 |
