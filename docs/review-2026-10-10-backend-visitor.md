# Event Radar 階段審查：後端主管與訪客體驗

日期：2026-10-10。審查對象：本機 `main` 的 `d87fd1a`。本文件是審查意見，以下問題尚未修正；不代表已公開部署。訪客心得來自實際操作本機網站，並非另一位真實使用者的訪談。

## 後端工程師主管批改

**定位：具技術深度的 Junior Backend 面試作品；目前不宜宣稱已可無人值守地對外提供準確的即時展覽資訊。** 強項是把異質來源轉成可搜尋資料、保留原始紀錄與待審邊界、交易式匯入、跨來源去重、欄位異動、PostgreSQL 佇列的鎖定／租約／重播，以及可追溯的技術決策文件。這些比單純抓取 HTML 更值得在面試說明。下一階段重點是資料正確性與來源營運證據。

### P1：疑似部分清單仍可能隱藏既有展覽

[`src/ingest.ts`](../src/ingest.ts) 先執行 `quarantineInvalidPrimaryRecords`（約 222–223 行），把本次變成 `review` 的既有主來源展覽設為 `visible=false`；之後才執行 `assessOfficialSourceCoverage`（約 294–303 行）。完整度判為 `deferred_partial` 時，目前只停止缺席候選比對，早先的隱藏仍會跟隨交易提交。

可重現的風險情境：上次可信清單有 6 筆展覽；本次來源原始資料仍列出 6 筆，但用於交叉核對的頁面暫時只解析出 2 筆，其餘 4 筆轉為待審。完整度判定發現可公開筆數驟降，卻來不及阻止那 4 筆在前面被隱藏。這與「部分清單先暫緩下架」的設計目標衝突。

修正決策應先區分「某筆來源明確顯示資料無效」與「整批資料疑似抓取不完整」。在造成展覽不可見之前評估完整度；疑似整批不完整時保留原始待審資料、發出警示，但不要只因交叉核對缺席就隱藏既有展覽。補一個跑完整條匯入流程的整合測試，斷言 `deferred_partial` 後舊展覽仍可見；也測明確失效資料的隔離行為。

### P2：公開網站會把疑似不完整的同步顯示為近期成功

[`src/ingest.ts`](../src/ingest.ts) 約 305–317 行在 `deferred_partial` 時仍寫入 `succeeded`，並更新 `last_official_success_at`。[`src/server.ts`](../src/server.ts) 的 `/museums` 資料新鮮度依成功時間與最近嘗試狀態計算；[`frontend/src/main.tsx`](../frontend/src/main.tsx) 對 `recent` 顯示「最近 7 天內曾成功取得官方來源」。因此站長的健康頁雖可看到完整度警告，訪客仍可能以為該館清單完整。

建議讓公開 API 傳出最近官方完整度狀態，並在館所／搜尋結果附近提示「官方清單疑似不完整，請核對館方」。也可將部分成功與完整成功分開記錄，避免刷新代表完整同步的時間戳。此處的使用者文案須與實際可保證的內容一致。

### 營運與驗證證據

本機 `npm run sync:status` 顯示 5 個來源；目前只有科工館有官方成功同步時間，其餘 4 個來源的 `lastOfficialSuccessAt` 為空、健康狀態為 `never`。海生館有 26 筆、故宮北院有 15 筆待審。這反映來源接入與審核仍在進行，不能用測試通過取代實際每天同步的穩定度證據。

本次審查的單元測試 34/34 與型別檢查通過。這次審查沒有重新完成 PostgreSQL 整合測試；前一實作階段曾在隔離 PostgreSQL 通過既有整合套件，但它尚未涵蓋上述 P1 情境。修正後應重跑整合測試、紀錄連續多日同步結果，並檢查解析失敗、待審量與來源新鮮度。

## 訪客實際操作心得

測試環境：本機 `http://127.0.0.1:3000/`，桌面瀏覽器；未測手機、螢幕閱讀器或實際購票結帳，也未訪談其他使用者。

- **找展覽的流程順暢。** 在搜尋區選「臺南市」後，博物館選項會收斂到奇美；結果縮為 1 場。選擇奇美及免費條件後出現清楚的空狀態與「清除篩選」，不會留下讓人誤解的空白頁。
- **票務資訊有實際幫助。** 展覽卡可展開；奇美特展票價與一般入館票價分開列出，附館方票價和購票入口，並標示人工核對日期。這能避免把一般門票錯當特展門票。
- **參觀提醒值得保留。** 奇美頁顯示一般休館日及例外需查館方；圖鑑頁有常設內容、開館資訊、來源連結與照片署名，視覺有一致的考古探索氣氛。
- **中優先級操作問題。** 從奇美圖鑑點「查奇美近期特展」，網址帶入 `?museum=chimei#explore-title`，篩選也正確，但頁面初次載入仍停在首頁頂部；再次點首頁導覽的「探索特展」才捲到搜尋區。應在 React 內容掛載後處理網址錨點，讓回到展覽的入口真正把使用者帶到結果。
- **可改善的連續性。** 上方已選奇美，往下看票務索引仍預設「全部館所」。兩區若刻意獨立，需更明顯說明；若希望規劃行程一氣呵成，可把館所／城市選擇同步過去。

目前最應先修 P1，再修 P2 與跨頁錨點。上述修正後，以官方來源的實際連續同步紀錄和待審處理結果判斷是否適合公開；首頁視覺與更多博物館數量不是此階段的瓶頸。

## 修正追蹤（2026-10-10）

P1、P2 與跨頁錨點已在後續提交修正。完整度判定現在先於因待審資料造成的可見性變更；疑似部分清單保留舊展並保存待審紀錄。公開 API 增加 `coverageStatus`，網站與資料新鮮度並列提示。從奇美介紹頁返回展覽頁已在本機瀏覽器驗證會捲至搜尋區。隔離 PostgreSQL 整合測試加入科工館 6→2→6 筆案例並通過。這些修正不等於已核對所有館方資料，仍需實際連續同步證據。
