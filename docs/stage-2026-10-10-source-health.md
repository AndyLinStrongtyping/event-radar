# 階段紀錄：本機來源健康觀測

日期：2026-10-10。Event Radar 仍是本機 MVP；這是只讀排查工具，沒有啟用線上排程、遠端監控或通知。

## 問題與決策

原本 `sync:status` 把同一次工作中的每次重試都算進七日嘗試／失敗筆數。例如第一輪失敗、第二輪成功，會顯示一筆失敗，但這次工作最終其實成功。現在以 `sync_id` 取每次工作的最後一次嘗試，再計算七日工作數、最終失敗數與失敗率；另列有重試的工作數，不掩蓋曾遇到的暫時性問題。

來源狀態先看最近一次工作是否失敗，再看最後成功取得官方來源是否超過七天；沒有官方成功紀錄顯示「尚無」，沒有可證明的工作狀態顯示「待確認」。近期成功但有待審來源紀錄或新缺席候選，顯示「有待審」；其餘才顯示近期正常。這是人工排查順序，不是來源完整性、展期有效性或當天開館的保證。七天只是同步健康提醒門檻，博物館展覽資訊本身不需要每天變動。

## 操作與驗證

`npm run sync:status` 讀取 Git 忽略的 `.env`，回傳每館 JSON 與狀態；本機 `npm run admin` 登入後的 `/health` 顯示同一份資料的中文摘要。報告包含最近官方成功、七日工作最終失敗率、重試工作、待審來源與新缺席候選。失敗率在沒有工作紀錄時為 `null`，不假裝成 0%。

本機 `npm run typecheck`、`npm test`（32/32）及 `npm run test:integration` 通過。隔離 PostgreSQL 測試驗證兩列嘗試、同一 `sync_id` 只算一份工作，重試成功的最終失敗數為零；登入後健康頁可讀、未登入不可讀。本機現有資料執行 `npm run sync:status` 成功：五館中只有科工館有可證明的近期官方成功工作，其餘不能宣稱近期同步；這是現有紀錄的呈現，不代表館方實際資料已停止更新。技術取捨見 [ER-32](technical-decisions.md#er-32本機來源健康觀測已實作本機驗證)。
