# 第五階段：展覽狀態、免費篩選與索引評估

日期：2026-10-05，臺灣時間。網站仍只在本機；線上每日同步及公開部署仍未啟用。

搜尋新增 `asOf` 基準日及 `status`：未結束、展出中、即將開始、已結束、全部。展期起日與迄日均包含當日，狀態隨基準日計算，不儲存容易過期的固定狀態。`from`／`to` 保留為獨立的展期交集範圍。首頁亦可切換狀態與基準日，卡片顯示展覽狀態。

`admission=free` 僅搜尋票價欄明確等於「免費」「免費入場」「免門票」的紀錄。來源沒有票價、只有一般售票提示或文字含糊時，一律視為未知，不推斷免費；卡片仍提示回官網核對。現有真實匯入資料大多缺票價，因此目前免費結果可能為空。預覽另有明確標示的模擬免費資料，僅在勾選測試資料時可見。後續若要涵蓋更多免費展覽，需逐館取得官方票價資料與有效期，再以可追溯來源補入，不能只為填滿結果而猜測。

資料庫索引實查：目前本機 `exhibitions` 28 筆，已有主鍵、`(museum_id, source_key)` 唯一鍵、`(end_date,start_date,id)` B-tree 及 `to_tsvector('simple',title)` GIN。對未結束、明確免費和 `%科學%` 關鍵字執行 `EXPLAIN (ANALYZE, BUFFERS)`，PostgreSQL 均以小表循序掃描完成，執行時間約 0.03–0.47 ms。現在新增多個索引會增加寫入與維護成本，沒有可見查詢收益，所以本階段**不新增索引**。既有標題 GIN 索引不服務目前的 `ILIKE '%詞%'`；資料量增加後若關鍵字搜尋變慢，先量測 `pg_trgm` GIN 的效果，再決定是否取代它。若城市／館所與狀態組合的列表查詢開始掃描大量資料，再比較部分索引 `(museum_id,start_date,id) WHERE visible AND NOT is_sample`、`(end_date,start_date,id) WHERE visible AND NOT is_sample` 與實際查詢計畫，不預先建立。

驗證：隔離 PostgreSQL 整合測試建立免費模擬展覽，檢查三種狀態、免費篩選、模擬資料預設隱藏與無效參數 400；CI 同時檢查公開 API JSON 格式。這些測試不依賴館方即時資料，因此能穩定檢出搜尋行為回歸。
