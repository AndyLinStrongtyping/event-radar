# 同步品質閘門｜2026-10-10

之前已有空來源失敗與逐筆待審，但若一整批來源紀錄**全部無法公開**，匯入仍可能回傳成功。對每日同步而言，這會把來源品質退化記成成功嘗試。這一階段改成「0 筆可公開展覽」一律需人工核對。

處理流程：解析來源後，先套用已核對且來源 hash 仍相同的人工補正，再寫入 `source_records`。如果仍是 0 筆有效展覽，將 `ingestion_runs` 記為 `failed`，保留原始紀錄、待審原因和計數，提交這些審查資料，程序以非零碼結束；`last_success_at` 不更新。若來源根本回傳 0 筆，則直接失敗。批次含有效展覽和待審資料時照常匯入有效展覽，待審仍不出現在公開搜尋。這類資料品質錯誤不符合暫時性網路重試條件；來源人工核對或補正後可重跑。

隔離 PostgreSQL 整合測試涵蓋：空陣列失敗、全部待審時原始紀錄與失敗計數留存、最近成功時間不前進、人工補正後可重新成功、來源變動時舊補正撤回並標失敗。單元測試確認品質錯誤不觸發暫時性重試。2026-10-10 本機驗證：`npm test` 30/30、`npm run typecheck`、`npm run test:integration` 通過。網站仍是本機 MVP；這項變更沒有啟用線上每日排程。

目前採保守規則，若某館確實暫無限期展也會標為需人工核對。日後只有在該館官方來源能可靠表示「本期為零」且實測過後，才為該來源設計明確的零筆成功條件，不能以空陣列默認來源健康。
