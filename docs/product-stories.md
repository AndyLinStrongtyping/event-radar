## 使用案例（Use Case）

### UC-01 查展與行前核對（US-01～03）

角色：一般訪客。觸發：想安排某城市某日期的看展。前提：網站可開啟，不須登入。

主流程：選城市 → 選館／日期／狀態 → 查詢 → 展開展覽 → 確認票價適用範圍與來源 → 開啟官方頁。

替代流程：零結果時調整條件或查館方；請求失敗顯示錯誤與重試，不能偽裝為零結果；來源陳舊或部分涵蓋時仍提示限制。結束狀態：訪客取得可核對的候選展，不代表已買票或預約成功。

### UC-02 主題與展品探索（US-04、08～10，文章部分規劃）

角色：文化／科普讀者。觸發：主題卡或館所連結。前提：文章完成編輯核對並發布。

主流程：進主題頁 → 選文章 → 看摘要與觀察重點 → 閱讀延伸內容／來源 → 選下一篇、館所或已核對的展覽。

替代流程：沒有可靠圖片時用明示示意圖或官方連結；展期已過改歷史關係；來源失效時編輯補證或撤回有疑慮段落，不移除其他正確內容。撤稿頁須有清楚不可用訊息，相關入口同步移除。

### UC-03 每週匯入與異常處理（US-05～07、12）

角色：排程與站長。觸發：每週工作或授權手動重跑。前提：來源啟用、憑證有效。

主流程：建立唯一工作 → 取來源 → 驗證與轉換 → 比對既有資料 → 交易保存及變更紀錄 → 記錄成功與來源狀態。

替代流程：暫時失敗有限重試；耗盡留下失敗及人工重跑入口；清單異常暫緩完整度／缺席判斷；內容無法驗證進待審；個別連線失敗保留可用舊資料。成功抓取不等於完整收錄，缺席不直接等於取消。

### UC-04 編輯文章與修訂（US-08～11，規劃）

角色：站長／編輯。觸發：新題目或內容更正。前提：選題在試點範圍。

主流程：簡綱與來源 → 原創整理 → 圖像條件確認 → 事實及展示關係核對 → 預覽與連結檢查 → 發布 → 記錄修訂及成效。

替代流程：證據不足退回草稿；圖片不可用換素材；已發布重大錯誤先撤回／更正並留修訂紀錄。產出只代表該版審核通過，不能宣稱永久正確。

## 驗收紀錄要求

每次交付記錄需求ID、測試資料、操作或命令、預期／實際結果、版本、環境與日期。自動測試、人工檢查、線上觀察分開；未執行填待驗證。不得以本文件的驗收條件存在，取代真正的測試結果。
