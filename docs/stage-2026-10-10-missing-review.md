# 階段紀錄：缺席候選人工核對

日期：2026-10-10。此階段限本機；未推送、未公開部署、未啟用線上每日同步。

## 問題與處理

前一階段能指出「展覽未再出現在成功取得的官方清單」，但站長核對後無處留下結果，後續也無法區分新缺席觀測與已看過的觀測。這次新增 `db/010_missing_candidate_reviews.sql`：保留每次人工核對的審查人、證據連結、說明、結論及當時連續缺席次數，候選另記最近已核對的缺席次數。一次觀測只能核對一次；新一次官方同步仍缺席，就再次待核對。來源重新出現後，再次缺席會開新週期，舊核對歷史保留。

本機管理頁 `/missing/record` 展示館方原頁與歷史，登入者可提交「核對後保留」或「需後續追查」。表單沿用登入、同源與 CSRF 保護；交易鎖定候選，證據必須是與原始來源同網域的 HTTPS 網址。兩種結論**都只記錄，不修改展覽日期或可見狀態**。網域驗證不能代替人眼核對內容；缺席仍不等於取消。

## 操作與驗證

先 `npm run migrate`，設定至少 16 字元的 `EVENT_RADAR_ADMIN_PASSWORD` 後執行 `npm run admin`；開啟本機 `/missing`，點候選展覽核對。`npm run review -- --missing` 顯示 `needsReview`、`reviewedMissedRuns`。不要在未查證館方頁時提交紀錄。

本機 `npm run typecheck`、`npm test`（30/30）及 `npm run test:integration` 通過。整合測試使用隔離 PostgreSQL，驗證登入、CSRF、無關證據網域遭拒、核對成功、相同觀測重送遭拒、新一次缺席重新待審、重新出現再缺席開新週期，以及展覽維持可見。這是合成官方清單的行為測試，不是實際館方取消事件。技術取捨見 [ER-31](technical-decisions.md#er-31缺席候選的人工核對紀錄已實作本機驗證)。
