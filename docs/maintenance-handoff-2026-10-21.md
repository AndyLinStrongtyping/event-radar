# Event Radar 暫停功能擴充前的維運交接

截至 2026-10-21，公開預覽、展覽搜尋、館所導覽、歌劇院節目、海洋與化石靜態專區、Neon PostgreSQL、來源審查與變更紀錄均已實作。六個獨立來源工作在 [10/20 第一次真實週排程](stage-2026-10-21-first-weekly-schedule.md)完成；故宮北院雲端同步仍關閉。這是**能公開展示、需定期照看的測試產品**，不是已證明可無人維運的完整收錄服務。

## 暫停開發期間需要照看的事

1. 每週二查看[每週同步工作](https://github.com/AndyLinStrongtyping/event-radar/actions/workflows/weekly-sync.yml)：六個啟用工作有沒有成功、北院是否仍略過。第一次排程實際於臺灣時間 07:40 啟動，比設定時間晚；不要只在 04:15 看。下一次真實週排程尚未發生，不能先標為跨週穩定。
2. 成功工作也看匯入摘要。`deferred_partial`、來源鍵突然變動、待審增加或單館 0 筆可公開資料時，依[操作手冊](operations.md)核對官方頁；不要因工作呈綠色就認定清單完整。國美館 10/20 的部分涵蓋已核對為一檔到期展覽並更新比較基準，但仍待下次成功同步重評；海生館 25 筆缺完整展期，繼續待審。
3. 檢查 [Render 公開站](https://event-radar-preview.onrender.com/) 的 `/health`、首頁搜尋及館所來源狀態；若免費服務休眠，首次回應可能較慢。若 API 或資料庫失效，先查 Render 日誌與 Neon 狀態，再看是否為 Secrets、額度或 migration 問題。`museums.qcngt.com` 是另一個網站，不能用來驗收 Event Radar。
4. 定期用[備份與還原流程](operations.md)產生資料庫備份並驗證可讀；已於 10/18 與 10/21 兩次完成正式資料的本機隔離還原，尚無自動異地備份。備份與密碼不得推進 Git。
5. 若資料來源、展期或圖片有爭議，以館方當期頁重新核對；缺日期或來源不明的候選留在待審，不為了增加搜尋筆數而公開。
