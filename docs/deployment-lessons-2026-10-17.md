# Event Radar 首次部署：遇到的問題與資料處理

**紀錄日期：2026-10-17。** 這是已發生、已核對的免費技術預覽部署紀錄，不把單日成功寫成跨週穩定性。設定畫面與重建命令另見[圖解設定手順](deployment-walkthrough.md)；架構取捨見 [ER-85～87](technical-decisions.md)。

## 這次實際完成什麼

GitHub `main` 的程式經 Render Blueprint 建成同源 React／Node 公開站，接 Neon PostgreSQL。Render 顯示 `event-radar-preview` **Live**，執行版本 `8d78297`；資料庫套用 **25 份 migration**。本機工作站連遠端 Neon 完成六個限期展來源的手動同步，網站單次驗收可讀 **11 間館所、27 筆未結束且合規的可搜尋特展**。海生館另有 **9 筆當日節目**、臺中國家歌劇院 **20 筆節目**，奇美 **10 筆人工核對活動候選**；這些屬不同資料類型，不能相加當作 66 筆特展。

## 遇到的問題、處理方式與留下的限制

| 問題／觀察 | 這次怎麼處理 | 尚未解決或不能宣稱的事 |
| --- | --- | --- |
| **Neon 的連線資料是完整資料庫憑證**。截圖過程曾讓舊密碼出現在畫面。 | 旋即重設密碼，使舊值失效；更新 Render `DATABASE_URL` Secret 與本機 Git 忽略的 `private/deployment-credentials.env`。公開手順重新擷取畫面，避開 Connect 視窗，Render 環境值保持遮蔽。 | Git 忽略不阻止 OneDrive 同步本機私密檔；站長仍須決定是否改放密碼管理器。不能把新密碼放入文件、issue、CI log。 |
| **Neon 連接器的進一步授權要求超出單一專案需求**。 | 只核准 Event Radar 單一專案範圍；沒有為方便操作而核准整個帳號的專案／組織建立與刪除權限。改用已登入控制台與本機受控命令完成必要工作。 | 將來若真的需要擴權，需另行評估用途與範圍；不是本次部署的前置條件。 |
| **Render 免費 Web Service 沒有可用的獨立 pre-deploy command／dashboard shell**。空白 Neon 庫不能只開 Web Service 就期待資料出現。 | `render.yaml` 的 build 依序執行 React build、`npm run migrate`、`bootstrap-preview.mjs`。bootstrap 只在沒有當期／未來合規特展時嘗試既有官方來源；全失敗則讓建置失敗，避免發布空白展覽站。 | migration 在服務真正 Live 前就可能已寫進 Neon；程式回退不會自動回退 schema。後續 schema 變更應先備份並保持前後版本相容。 |
| **Render 建置環境抓故宮北院來源連續三次 `fetch failed`**。 | 沒有改用假資料或關閉資料檢查。改由本機工作站使用同一套 `sync` 命令連 Neon；先匯入科工館 **7 筆可展示展覽**使建置檢查通過，再逐館同步故宮北／南院、科博館、海生館、國美館。 | 根因仍未確定。只能證明本機到館方與 Neon 可連、Render 到 Neon 可連；不能推論 Render 到所有館方皆穩定，也不能啟用無人值守同步。 |
| **來源資料不是全部能直接上架**。 | 正式來源逐筆驗證展期、館別與官方 HTTPS 網址；缺資料或不合規者留下原始紀錄與待審理由，不進公開特展搜尋。當時北院 **15 筆**、海生館 **25 筆**、科工館 **1 筆**待審。 | 27 筆是當時可搜尋結果，不是六館所有展覽，也不能把待審項目當作來源缺失或館方取消。 |
| **GitHub CI 版本與 Render 線上版本不同**。 | 分開記錄：文件提交 `499bcc2` 的 GitHub Actions 成功，Render 當時仍執行 `8d78297`。每次發版看 Render 的 Live SHA，再跑線上 smoke。 | `main` 有新提交不代表網站已更新；目前 `autoDeployTrigger: off`，需要手動部署。 |
| **免費站會休眠，且尚未準備對搜尋引擎開放**。 | `PUBLIC_BASE_URL` 留空，頁面回 `X-Robots-Tag: noindex`；用 `--expect-noindex` 驗收。這是公開可讀的技術預覽，不是私人站。 | 閒置冷啟動可能較慢；休眠時平台可能代回不利爬蟲的 `robots.txt`。沒有 Search Console 收錄、真實流量或跨日可用性證據。 |

## 展覽資料實際怎麼處理

```text
館方公開 JSON／HTML
    → 來源 Adapter 解出原始列與館方連結
    → 日期、館別、標題與 HTTPS 網址驗證
    → 有效列正規化；無法確認的列保留原始資料並待審
    → 官方清單完整度檢查
    → 同一館所內比對來源鍵／網址、保守去重與欄位異動
    → PostgreSQL 交易寫入展覽、來源別名、變更史及匯入結果
    → 唯讀 API → React 搜尋畫面
```

1. **分來源擷取與隔離失敗。** `npm run sync -- --source <館別>` 逐館執行；暫時性失敗最多重試三次，`sync_attempts` 保存嘗試與結果。某館失敗不需要刪除其他館資料，也不能把最後成功時間當成剛更新。這次故宮北院在 Render 失敗，並沒有阻止本機逐館完成其他同步。
2. **日期與來源驗證先於公開。** [`normalize.ts`](../src/normalize.ts)只接受真實的 `YYYY-MM-DD` 起訖日，拒絕結束早於開始、館別不符、缺標題或非對應館方 HTTPS 網址。原始資料與待審原因保存在 `source_records`。**零筆可公開展覽**的批次會保存可審紀錄，但匯入狀態記失敗，不能把來源健康時間往前推。
3. **去重、冪等與變更紀錄。** 同館同來源先以穩定來源鍵／官方網址找原紀錄；跨來源以相同官方詳情網址優先，網址不同時只有展名、展廳相同且展期重疊才考慮合併，歧義時停止等待人工判斷。重跑相同資料只更新最後看見時間；欄位真的變動才更新展覽並寫入 `exhibition_changes`。來源別名放在 `exhibition_sources`，不把相同活動重複顯示。
4. **清單異常不等於展覽取消。** 首次官方同步只建立 coverage 基準。之後若來源筆數或來源鍵大幅變動，限期展流程將清單標為 `deferred_partial`，暫緩「缺席」判定；有效新展仍可匯入，舊展不因不完整清單自動下架。一般缺席也只建立待人工核對的候選。這是防止館方網頁異常或解析器改版造成大量誤刪。
5. **查詢只呈現可公開且符合篩選的項目。** `/exhibitions` 讀已入庫的合規展覽，依目前日期顯示未結束的結果；票價未知不推斷為免費。當時結果為 27 筆，網站提供館方來源連結，出發前仍需向館方核對。

表演、當日節目和奇美候選**沒有硬塞進相同的特展日期模型**：

| 類型 | 本次處理 | 公開解讀邊界 |
| --- | --- | --- |
| 歌劇院表演 | 官方 `place=1` 清單與詳情轉成 `domain_events`／`event_sessions`；本次 20 筆，場次異動另留紀錄。 | 只涵蓋此篩選清單；`scheduled` 不保證有票。清單異常整批拒收，需核對。 |
| 海生館當日節目 | 官網當日頁轉成節目與時段；本次 9 筆，保存觀察日期快照。 | 歷史快照不是未來固定節目表，特殊開／休館另外核對。清單大幅縮水整批拒收。 |
| 奇美活動 | 人工核對快照的 10 筆候選保留來源與核對時間。 | 不是穩定自動來源，也沒有混入已驗證的限期展搜尋結果。 |

## 這次的驗證與下一個判斷點

- Render：Live、執行 SHA `8d78297`、Neon 25 份 migration 已套用。
- 公開網址執行 `npm run smoke:deploy -- https://event-radar-preview.onrender.com --expect-noindex`：健康檢查、資料庫、React 資源、館所／特展 API、館所頁與化石圖片通過；**11 間館所、27 筆可搜尋特展**。
- 資料仍由本機手動同步；來源待審仍存在。**下階段先追查 Render 到各館方的連線、持續觀察資料品質與跨週可用性，再決定是否啟用雲端排程與索引。** 無法從這次單日驗收推出真實使用量、SLA 或營利可行性。

## 把預覽連結分享給朋友時

這個網址本來就公開可讀，可以邀朋友試用並收集「搜尋能否找到想看的展」、「手機是否好操作」、「哪些館所資訊不清楚」等回饋。分享時請明示**測試版、非館方官方網站**；展期、票價、休館及購票資訊仍以活動卡片連到的館方公告為準。免費服務閒置後第一次開啟可能較慢，來源目前由本機手動更新，不能說成即時資訊。`noindex` 只是不主動要求搜尋引擎收錄，**不是密碼保護**，限動轉傳後任何拿到網址的人都能瀏覽。

可使用的簡短說法：「我做的 Event Radar 博物館展覽測試版上線了，歡迎試用、回報找不到或看不懂的地方。活動與開館資訊出發前請再到館方官網確認。」這是測試邀請，不代表已有穩定流量或正式營運數據。
