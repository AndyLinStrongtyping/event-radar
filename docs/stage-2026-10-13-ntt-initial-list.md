# Phase 3 續作：歌劇院初始節目清單覆蓋

核對日：2026-10-13（臺灣時間）。維持本機開發；公開部署與營利評估不在這一階段啟動。

## 問題與處理

原本 `nttDetailUrls` 在初始頁取得五個館方節目連結後即停止，即使後面仍有更多可見卡片，也沒有告知站長。現在會先讀完整初始 HTML，收集並去重所有符合館方詳情路徑的連結。上限為 30 筆，與本機 `importDomainEvents` 單批限制一致；若超過便整批失敗，避免網站把截斷的資料當作成功同步。同步詳情之間等待兩秒；任一詳情無法取得或解析時，整批不寫入。

本次沒有推測或呼叫「MORE」背後的未文件化介面。因此輸出仍標為 `sampled_list`，只宣稱**初始頁可見清單**，不宣稱歌劇院全部節目都已收錄。若未來清單超過 30 筆，先查明分頁及合理的分批保存方案，再提高覆蓋率。

## 驗證與剩餘工作

- 2026-10-13 以一次只讀請求取得[官網初始清單](https://www.npac-ntt.org/program/events?place=1)：HTTP 200，HTML 約 108 KB，辨識出 19 個不同官方詳情連結。
- 以兩秒間隔只讀核對 19 個詳情：全部 HTTP 200，皆可解析至少一個完整年份的場次；沒有寫入資料庫。
- `npm test` 60 項通過，`npm run typecheck` 與 `npm run build:web` 通過。整合測試曾嘗試，但本機 PostgreSQL `127.0.0.1:5441` 未啟動，連線被拒；因此不能宣稱本次擴量已完成資料庫整合驗證。
- 下一步是啟動隔離 PostgreSQL 整合測試、手動執行一次 19 筆同步並核對 API；之後再查「MORE」分頁、售罄／取消／延期逐場證據及跨日穩定。來源清單縮水時仍不能依缺席推論取消。

2026-10-14 更新：隔離 PostgreSQL 已恢復，19 筆**合成節目**的整批入庫、同批冪等及 API 清單整合測試通過。10/13 官網所見的 19 筆詳情尚未實際寫入本機資料庫；當期官網清單可能已改變，下一次手動同步應重新核對後再執行。其餘 MORE 覆蓋與逐場票務證據仍未完成。

同日稍後已重新讀取官網初始清單並實際手動同步 19 筆（新增 14、未變 5），本機公開 API 回 `total=19`；前段「尚未寫入」只描述當時進度。首次嘗試因一筆詳情逾時而整批停止，加入有限重試後成功；本次沒有讀取 MORE 後續清單。

2026-10-14 後續核對：官網「MORE」不是伺服器分頁，而是將 `#glch` 內已在同一 HTML 的 `hide` 卡片逐批顯示。先前 19 筆掃描事實上已包含當時的預藏卡片；上段「沒有讀取 MORE 後續清單」是當時未查證按鈕行為的判斷，現由 [ER-64](technical-decisions.md) 修正。Adapter 加入按鈕行為變更時停止匯入的保護；同日再次手動同步 `place=1` 清單，接受 20 筆（新增 1、未變 19）。其他篩選條件及跨週來源穩定尚未驗證。
