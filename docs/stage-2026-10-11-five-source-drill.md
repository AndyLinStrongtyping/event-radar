## 發現與修正

來源健康報告把後三館標為 `needs_review`，但公開 API 原本只顯示 `dataStatus=recent`。現在 `/museums` 加 `pendingReviewCount`；網站來源提示指出待審紀錄可能含歷史資料且不進搜尋。`recent` 仍只表示近期成功取得官方來源。匯入 CLI 日常輸出也移除完整來源鍵清單，以免大量來源時灌滿 CI 日誌；來源鍵仍存資料庫供審查。

原先佔用本機 3000 埠的程序啟於 2026-10-10，回應缺少新版欄位。先用目前程式在 3006 埠核對：五館均回 `lastOfficialSuccessAt` 與 `coverageStatus=baseline_created`，搜尋總筆數為 8／7／1／4／7。再停止已確認的舊 Event Radar 程序，以隱藏背景程序在原 3000 埠啟動目前版本。`GET /museums` 實測待審數依序為 0／0／15／26／1；首頁回應載入含待審提醒的新 React bundle。3006 暫用程序已停止。
