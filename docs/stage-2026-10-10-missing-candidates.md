# 階段紀錄：官方清單缺席候選

日期：2026-10-10。Event Radar 仍是本機 MVP；此階段沒有啟用線上排程或公開網站。

前一階段已處理「來源紀錄仍存在，但資料轉為待審」的情況。這一階段處理另一個問題：原本有效的展覽從後續官方清單消失時，舊資料仍留在搜尋。來源清單可能不完整，因此不能把消失直接解讀為取消。

成功的 `--official` 匯入若有有效展覽，系統會比較該 provider 先前公開、未結束的來源別名與本次來源鍵／官方網址。缺席者寫入 `source_missing_candidates`，保存首次及最近缺席時間、連續缺席次數、對應展覽與匯入 run。重新出現，或由另一有效 provider 接手，候選自動結案。當次數量記在 `ingestion_runs.missing_count`。本機 `npm run review -- --missing` 與登入後的管理頁 `/missing` 可查看並連到館方原頁。

候選**不會自動隱藏展覽、改日期或宣稱取消**。手動檔案／快照不參與；空來源、全待審或其他失敗匯入也不參與。初次執行時，過往來源的有效舊展可能產生候選；需由人確認來源是否完整及館方是否公告下架。現階段沒有人工結案按鈕或告警通知。

本機驗證：`npm test` 30/30、`npm run typecheck`、`npm run test:integration`（隔離 PostgreSQL）通過，`npm run migrate` 已套到本機資料庫。整合測試檢查兩次缺席累計、手動快照不增加次數、重新出現結案、展覽仍可查及登入後管理頁可讀。技術取捨見 [ER-30](technical-decisions.md#er-30官方清單缺席候選已實作本機驗證)。
